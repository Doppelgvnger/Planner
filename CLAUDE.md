# Planner
Planner web app for the user's girlfriend (marketing project manager). UI in English; the user talks in Russian. Plain single-file HTML/CSS/JS, no build. Local git repo (branch `main`, no remote); commit each fix separately. Requirements are still being discovered module by module.

## Run
Open `index.html` in a browser (works from `file://`).

## Layout
- `index.html` — whole app. Tabs: Calendar (placeholder), Campaigns, Timeline; both built tabs share the same `campaigns` data, dialog and destination filter (`renderAll()`). Open tab kept in URL hash (`showView`).
- Campaigns: one column per campaign (header click = edit, header drag after 6px = reorder with ghost/placeholder + `flipCols`; order in `localStorage` `planner.colorder.v1`, else by first start date). Header chevron toggles `c.compact` (name + status only; `.col-details` height-animates so tasks ride along). Detailed/Compact board toggle (`dense`, `localStorage` `planner.dense.v1`) morphs columns via View Transitions (`view-transition-name: col-<id>`). Native board scrollbar hidden; custom `.hscroll` pinned to the screen bottom (`syncScrollbar`). Task `showSegs` hides market chips on the card. Park button sets `c.parked` (timestamp) → campaign leaves the columns and shows as a tile in the left rail (`#park`, `tileHTML`); tile click edits, its own button unparks (`setParked`, morphs via the shared view-transition-name). Ended parked campaigns fall back under "Show ended". Status pills (`statusHTML`/`statusPill`): live green, soon yellow, ended red, one line per group of markets when states differ; lead gen appears only in Timeline's "Coming up" (`statusHTML(c, true)`), never on the Campaigns tab. Ended campaigns hidden behind "Show ended". Tasks live on the campaign: `tasks[{id,text,done,doneAt,urgent,archived,due,desc,segments,subtasks,createdAt}]` (`normTask` fills missing fields). Open-task order = array order; `placeTask` inserts by urgent/due on create or when due/urgent changes, handle-drag (pointer events, ghost + placeholder) overrides it and can move tasks between campaigns. Click a task → task dialog (draft, saved on Save). Motion via FLIP in `withFlip` (falls with bounce going down, springs going up). Done tasks sink with an archive button; Archive dialog restores/deletes. Nothing is deleted outright: campaigns (with tasks) and tasks (dialog delete, archive delete) go to Trash (`localStorage` `planner.trash.v1`; campaign `{c, at, pos}`, task `{type:'task', t, cid, cname, color, at}`). Restore puts a campaign back at its board slot and a task into its campaign (restoring that campaign too if it's in Trash). Only permanent deletes in Trash ask, via the in-page `ask()` dialog — never use `confirm()`. New campaigns join a hand-made board order by date (`placeColumn`). Status pills from `statusHTML(c)` (shared with "Coming up").
- Timeline: rows = segments (US, CA·EN, CA·FR, MX, BR), columns = days. Drag across a row → create campaign; click a bar → edit/delete. Campaign = name, segments[], destinations[] (DTC/Sephora), start/end, color (preset name or custom hex), overrides {segId: {start,end}} for markets moved off the campaign dates (`datesIn(c, seg)`; "Coming up" uses the span across markets), optional leadgen {segments (subset of campaign's), start, end, overrides} (`lgIn(c, seg)`) drawn hatched in the campaign's lane; default 7 days ending the day before campaign start; overlap only warns. Per-market date UI is `marketEditor()`, used twice (campaign + lead gen). Destination filter toggles; zoom 3 months (fixed day width, scroll) / 6 months (fit to width, Monday labels only). Data in `localStorage` key `planner.timeline.v1`; seeded with sample campaigns relative to today; old records without destinations load as both.

## Gotchas
- `crypto.randomUUID` is unavailable on `file://` — use the `uid()` helper.
- The in-app preview pane serves the page as a `data:` URL: localStorage and URL-hash changes are disabled there, and Firefox blocks pasted `data:` URLs. Test persistence in real Firefox via `file:///H:/Claude%20Code/Projects/Planner/index.html` (headless: `firefox -headless -no-remote -profile <tmp> --screenshot out.png <url>`).
- Segment flags are emoji rendered via the Noto Color Emoji webfont (Windows has no flag glyphs). Custom colors use the in-page wheel (`openWheel`), not `<input type=color>` — the user wanted it inside the site.
- Every campaign must have `tasks: []` — `renderBoard` throws without it (new campaigns are created with it; `load()` backfills).
- Header fold animates only `.col-details` height (spacing lives in `.col-details-in`); never animate negative margins on grid items, the track clamps at 0 and the motion stalls then jumps.
- Firefox fires a click on the row/header under the pointer after a pointer drag; a capture-phase listener swallows clicks within 400ms of `dragEndedAt`. Drag move/up listeners live on `window` because moving the dragged node in the DOM drops pointer capture.
- Visual direction taken from Inspo reference daybridge.com: light, Inter, pastel event bars, periwinkle accent.
